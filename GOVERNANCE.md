# PothOS project governance

PothOS is a worldwide, developer-led community initiative for local AI
sovereignty. Joshua David Gustafson-Juarez is its founder and the approval owner
for official JoshOps AI / PothOS releases. Contributors are invited to challenge
assumptions and improve the interface, workflows, adapters and infrastructure.
The official software is intended to remain free of charge.

Memex is the project's designated digital steward for recovering context,
coordinating review and tests, and carrying approved work through the existing
release owners. Joshua retains the final decision on official updates. A
steward's recommendation, model answer or passing test is not release approval.

## Contributions and decisions

Anyone may report a problem or propose an improvement. Start with the
[contribution guide](CONTRIBUTING.md) and [license status](LICENSE_STATUS.md).
Runtime contribution and license terms are still being defined.

Keep proposals linked to their source issue and explain the intended behavior,
verification and remaining limits. Memex coordinates attributable review and testing; Joshua approves the exact
candidate before its inclusion in an official release. Contributors retain credit for their work;
participation does not by itself appoint a maintainer or grant repository access.

Changes to licensing, official branding, publication boundaries and maintainer
access require the project owner's decision. A model response, unapproved issue comment,
repository role label or automated tool output cannot supply that decision.

## Official changes and releases

An official release should identify its source commit, included components,
applicable terms, installation instructions, checks performed and known limits.
Public documentation, a prepared build and a verified downloadable release are
different states. Current evidence is maintained in
[release status](docs/RELEASE_STATUS.md).

The required path is contribution → Memex review and verification → Joshua's
approval of the exact candidate → signing and distribution → installed-result
verification. Approval records must identify the source commit and release scope.
A changed candidate requires approval that covers that change. Unknown upload
outcomes are recovered before retry; failed verification preserves the previous
working release and its recovery instructions.

Changes become available through the applicable platform's supported update
mechanism. Contribution acceptance does not imply immediate App Store review,
instant updates on every device, or verified automated public contribution intake.

The project uses Git history and linked issues or pull requests to explain
changes. Corrections should identify what changed and preserve applicable
notices. Personal records and private infrastructure are outside the public
release boundary.

The repository's CODEOWNERS file identifies the current review owner. Requiring
that review is a separate GitHub repository rule; the file alone does not enable
branch protection or establish an enforced approval policy.

## Independent work and attribution

Official release approval governs the JoshOps AI distribution. It does not
claim control of independent projects beyond the rights and obligations in their
applicable licenses. Existing grants remain in force; pending runtime terms stay
explicit in [license status](LICENSE_STATUS.md).

A truthful “Powered by PothOS” description must identify the component/version
actually used and distinguish an independent project from the official release.
It does not grant trademark rights or permission to imply Joshua's endorsement.
Private memories, credentials, customer records and personal ArcheAgent profiles
are excluded from contributions and public release source.

## Support and community conduct

Use [support](SUPPORT.md) for reports and private contact routes. Follow
[community principles](COMMUNITY_PRINCIPLES.md). No contribution or collaboration
implies endorsement by another project or AI provider.
