# Voice and accessibility contribution plan

Voice and accessibility are part of making continuity useful to more people.
Existing native voice mechanisms are a starting point; no universal consumer
voice package or device qualification is claimed by this documentation.

## Useful contributions

| Area | Contribution and evidence |
| --- | --- |
| Keyboard access | Verify logical focus, visible focus and access to essential controls without a pointer. |
| Screen readers | Check names, roles, state announcements, reading order and meaningful error feedback. |
| Speech input | Document microphone permission, recording indication, stop/cancel behavior and recovery from interrupted input. |
| Speech output | Verify start, stop, interruption, volume behavior and a readable alternative. |
| Comprehension | Make important state and pending actions understandable without depending on color or sound alone. |
| Motor and sensory access | Test control size, adaptable presentation, captions or transcripts, and alternatives to voice-only actions. |
| Privacy | Explain on-device and external processing, retention and what leaves the operator's environment. |
| Platform qualification | Record device, OS, build and actual microphone/speaker observations. |

Use synthetic test content and consent-based feedback. Do not include a real
person's recordings, medical information, voiceprint or private memory as a
fixture. Rights to third-party audio assets must be reviewed separately.

Public code publication requires the licensing and privacy work in
[release status](RELEASE_STATUS.md). Robotics hardware/control work is outside
this prepared documentation release.
