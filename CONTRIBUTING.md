# Contributing to PothOS

Start with [the mission](docs/MISSION.md), [license status](LICENSE_STATUS.md)
and [community principles](COMMUNITY_PRINCIPLES.md).

## Where to begin

Use an issue to describe one concrete problem, its effect on a person and the
smallest improvement that could be checked. Documentation, privacy requirements,
accessibility feedback and reduced synthetic examples are useful now.

Use **PothOS**, **JoshOps AI**, **ArcheAgent** and
**PothOS Orb** accurately. Write ArcheAgent in full in public project prose.
Do not invent new product names, replace the existing continuity thesis or treat
the founder's private ArcheAgents as examples to distribute.

## Proposals and pull requests

Keep a change focused. Explain the relevant source, intended behavior,
verification performed and remaining limits. Distinguish a proposed mechanism
from a feature that has been implemented and demonstrated.

Runtime source contribution terms are not finalized. Discuss the proposal before
submitting a substantial code contribution or transferring rights. This document
does not establish a contributor license agreement, certify third-party rights
or grant access to a private system.

Do not include credentials, personal memory, embeddings, recordings, private
configuration or another person's records. Use synthetic examples.

The maintainer reviews official changes. A contribution does not automatically
create a project role or endorsement. Response times and release dates depend on
capacity. For private concerns contact [joshua@joshops.ai](mailto:joshua@joshops.ai).
