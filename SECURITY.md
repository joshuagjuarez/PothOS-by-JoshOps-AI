# Security reporting

For a suspected vulnerability, email [joshua@joshops.ai](mailto:joshua@joshops.ai)
with a concise description and a minimal reproduction. Do not put credentials,
private memory, recordings, tenant records or sensitive exploit details in a
public issue.

Start with the affected public version or document, expected behavior, actual
behavior and impact. Coordinate before sending sensitive files. No response-time
guarantee is established by this page.

The standalone runtime has not been released here. Claims about a private build
or service need their exact affected scope; a documentation issue does not
establish a vulnerability in every deployment.
